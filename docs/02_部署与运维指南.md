# 部署与运维指南

## 目的

说明当前已实现的生产运行结构、启动顺序、迁移与备份要求。本文不假设 Docker 化 FastAPI；当前 FastAPI 使用 systemd 与单 worker Uvicorn，AstrBot 作为独立 Docker 服务运行。

## 当前部署结构

```text
Internet
  │ HTTPS
  ▼
Nginx
  ├─ 静态前端构建产物
  └─ 反向代理 FastAPI
          │
          ├─ SQLite 持久化数据库
          ├─ APScheduler（进程内）
          └─ AstrBot Bridge HTTP Endpoint

AstrBot Docker
  └─ buptelec_bridge 插件与插件数据目录
```

Nginx、FastAPI、SQLite 与 AstrBot 应在同一受控网络环境内配置访问规则。Bridge 与 Internal API Token 不得暴露到前端。

## 后端启动

创建 Python 环境并安装依赖：

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

在已设置环境变量、确认数据库路径之后执行迁移：

```bash
.venv/bin/alembic upgrade head
```

开发启动命令：

```bash
.venv/bin/python -m uvicorn app.main:app --reload
```

生产应由 systemd 使用等价命令启动，不使用 `--reload`，并明确限制为单 worker。例如：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port <PORT>
```

## 单 worker 限制

Scheduler 在 FastAPI lifespan 中创建。若同一部署启动多个 Uvicorn worker 或多个应用实例，每个进程都会注册每日 Job，可能造成重复采集。因此当前版本必须满足一个 FastAPI 进程、一个 Uvicorn worker 和一个启用 Scheduler 的实例。

## 启动与升级顺序

1. 检查工作区版本、环境文件和 SQLite 路径。
2. 备份 SQLite 数据库及环境配置（密钥仅在受限备份中保存）。
3. 安装 `requirements.txt` 中新增的依赖，不升级无关依赖。
4. 执行 `alembic upgrade head`。
5. 重启 FastAPI，确认日志未输出密码、Cookie、Token 或 Fernet Key。
6. 确认 Nginx 配置有效并重新加载。
7. 单独重启 AstrBot Docker，确认 `buptelec_bridge` 插件已加载。

不通过删除 SQLite 文件、重置 Alembic 或覆盖现有数据来完成升级。

## 数据库备份

SQLite 是运行数据的唯一持久化数据库，应在迁移前和定期运维中备份：

```bash
cp <persistent-data-dir>/electricity.db <backup-dir>/electricity_YYYYMMDD_HHMMSS.db
```

备份完成后检查文件存在、大小合理且备份目录受访问控制。不将删除历史备份作为常规升级步骤。

同时需要受控备份：环境变量配置文件、`APP_UPSTREAM_SESSION_KEY` 的恢复材料，以及 AstrBot 数据目录（包含 QQ ID → UMO 路由映射）。

## Scheduler 运维

默认计划为 `Asia/Shanghai` 的每日 `04:00`，由 `COLLECTION_HOUR`、`COLLECTION_MINUTE` 配置。启动遗漏仅有五分钟 misfire 宽限；即便上午启动时间较晚也不会补跑凌晨的陈旧任务。

手动接口 `POST /api/v1/electricity/collection/run` 只执行当前已登录用户的一次采集，不会触发全量用户采集。生产排障时避免对全体用户进行高频或批量上游请求，避免系统性能下降，触发保护机制。

## AstrBot 运行边界

AstrBot 容器保持独立运行。插件需要能够访问 FastAPI 根地址，FastAPI 则通过配置的 Bridge Endpoint 调用插件公开的受保护接口。两个方向分别使用 Bridge Token 与 Internal Token，二者不应混用。

## 安全注意事项

- 使用 HTTPS 时将 `APP_SESSION_COOKIE_SECURE=true`。
- 不在 Git、镜像、前端构建产物或日志中保存隐私数据及保密文件。
- 以最小权限运行服务账户，并限制数据库、环境文件和 AstrBot 插件数据目录权限。
- 部署前需确认 `DEMO_MODE_ENABLED` 与 `APP_DISABLE_UPSTREAM_QUERIES` 是否符合目标环境。```
