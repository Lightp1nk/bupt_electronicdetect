# 开发进度记录

## 阶段 1：项目规划

- **目标**：明确课程项目边界和以正常校园认证为前提的实现原则。
- **成果**：确定单用户、本地运行、仅查询授权数据的初始范围。
- **下一步**：分析已有网页与请求行为。

## 阶段 2：学校电费接口分析

- **目标**：确定认证跳转和电费查询的实际请求顺序。
- **主要工作**：基于 Chrome HAR 与页面源码分析，确认 CAS 服务回调和 `/part`、`/floor`、`/drom`、`/search` 的字段关系。
- **工程问题**：上游内部 ID 不能由显示名称推断。
- **解决方案**：采用逐级动态获取 ID 的流程，不建立静态宿舍映射。

## 阶段 3：统一认证实现

- **目标**：用 Python httpx 完成正常统一认证。
- **成果**：实现 `BUPTAuthClient`，动态解析登录页 `execution`，并验证 `chong` 200 与 `/part e=0`。
- **工程问题**：不能依赖浏览器 Session，也不能硬编码 Cookie 或 ticket。
- **解决方案**：一个 `httpx.AsyncClient` 维护完整跳转和 Cookie Jar；日志脱敏。

## 阶段 4：BUPTClient 数据采集

- **目标**：实现宿舍层级查询与电费读数标准化。
- **成果**：实现 `get_buildings`、`get_floors`、`get_rooms`、`query_electricity`，并用 Pydantic 模型隔离上游字段。
- **工程问题**：不同校区的 `surplus`、`freeEnd` 语义不同。
- **解决方案**：按当前 `area_id` 规则映射可选标准字段，保留 `raw_data`。

## 阶段 5：认证 Session 管理

- **目标**：登录一次后由 FastAPI 进程复用 BUPT Session。
- **成果**：实现 `AuthSessionManager`、认证 API、最小受保护业务路由和 `session_probe.py`；实际验证连续请求无需重新登录。
- **工程问题**：并发登录、登出可能关闭正在使用的 client。
- **解决方案**：用 `asyncio.Lock` 保护状态修改与 client 租约；Session 失效即关闭并清理。

## 阶段 6：数据库与历史记录

- **目标**：保存标准化用电快照并提供历史与最新记录读取。
- **成果**：实现 SQLAlchemy Async + SQLite、`electricity_records`、Repository、`ElectricityService`、query/history/latest API 和临时数据库测试。
- **状态**：已实现但尚未完成真实上游数据库探针验证。
- **下一步**：运行 `database_probe.py`，验证真实写入与相同 source_time 去重。

- **状态**：规划中，尚未实现。
