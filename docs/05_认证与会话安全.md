# 认证与会话安全

## 目的

说明北邮 CAS 登录、浏览器本系统登录态、上游业务 Session 持久化和内存 Runtime Client 的安全边界。认证系统不保存密码，也不通过后台自动模拟重新登录恢复失效 Session。

## 登录流程

```text
用户输入北邮账号和密码
  ↓
AuthBootstrapService 创建临时 Bootstrap BUPTClient
  ↓
进入电费入口、跟随 CAS 重定向、提交登录表单
  ↓
完成 app callback 并验证业务 Session
  ↓
提取 AppBusinessSession
  └─ 仅 eai-sess / UUkey，且 Cookie domain 必须匹配 app.bupt.edu.cn
  ↓
关闭 Bootstrap Client（无论成功或失败）
  ↓
创建/更新 User 与加密 UpstreamSession
  ↓
创建本系统 AppSession token_hash，并向浏览器设置 HttpOnly Cookie
  ↓
创建该 user_id 的 App-only Runtime Client
```

完整时序图见 [authentication-sequence.md](diagrams/authentication-sequence.md)。

## 保存与禁止保存的数据

| 数据 | 处理方式 |
| --- | --- |
| 北邮密码 | 仅用于本次 Bootstrap 请求，不保存 |
| CAS ticket、execution、CAS Cookie | 不保存；Bootstrap Client 立即关闭 |
| `eai-sess`、`UUkey` | 以最小显式结构加密保存到 `upstream_sessions` |
| 浏览器 App Session 原始 Token | 仅通过 HttpOnly Cookie 交给浏览器；数据库只保存 SHA-256 hash |
| AstrBot UMO | 不保存于 FastAPI；仅由 AstrBot 插件数据目录维护 |

`AppBusinessSession` 的 Cookie 序列化字段仅为 `name`、`value`、`domain`、`path`、`expires`、`secure`。不会序列化整个 `httpx.AsyncClient` 或完整 CookieJar。

## 加密与浏览器会话

`APP_UPSTREAM_SESSION_KEY` 必须是有效 Fernet Key。首次使用时严格校验，缺失或非法时登录不能创建本系统登录态。系统不生成临时 Key，不采用明文降级。

App Session 默认有效期为 14 天，使用可撤销的随机 Token；每次读取当前用户时按配置间隔更新 `last_seen_at`，不会无限延长 `expires_at`。登出会撤销当前浏览器 Session，并只关闭该用户的 Runtime Client。

## Runtime Client Pool

`RuntimeSessionManager` 以 `user_id` 为键维护内存 Client：

```text
_clients[user_id] = App-only BUPTClient
_locks[user_id] = asyncio.Lock
```

读取上游数据时，`acquire_client(user_id)`：

1. 复用内存 Client；不存在时解密该用户 `upstream_sessions` 并恢复 Cookie；
2. 在用户级 lock 内验证 Session；
3. 请求完成后如 Cookie 轮换则重新加密持久化；
4. 发现失效时，仅关闭该用户 Client 并标记 `REAUTH_REQUIRED`。

不同用户可并行；同一用户上游请求串行。应用 shutdown 才调用 `close_all()`。

## Session 失效策略

- 无有效 upstream session：返回 `REAUTH_REQUIRED`。
- Runtime Client 验证或业务请求发现失效：标记该用户需重新认证。
- 不保存密码，不尝试后台 CAS 自动登录，不弹出或模拟交互登录。
- 用户下次在网页正常登录后才获得新的业务 Session。

## API 与服务间认证

浏览器 API 的 `get_current_user()` 通过 App Session Cookie 解析用户。AstrBot 不能使用浏览器 Cookie，而是调用 `/api/internal/chat/*`，以 `ASTRBOT_INTERNAL_TOKEN` Bearer Token 验证。两种身份机制职责独立。

## 安全注意事项

- 生产 HTTPS 必须启用 `APP_SESSION_COOKIE_SECURE=true`。
- 日志、测试输出与异常信息不得包含密码、Cookie、Authorization Header、Fernet Key 或 CAS ticket。
- 环境文件、SQLite 备份与 AstrBot 插件数据目录均需限制读取权限。
