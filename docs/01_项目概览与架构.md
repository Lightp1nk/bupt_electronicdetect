# 项目概览与架构

## 目的

本系统为北邮宿舍系统已登录用户查询并保存电费快照，基于历史快照提供电费统计预测与启动/余额预警，并通过 AstrBot 向已验证的 QQ 私聊发送通知、提供查询功能（只读）。

## 组件架构

```text
浏览器（Vue 3）
  │ HttpOnly App Session Cookie
  ▼
FastAPI
  ├─ Auth / RuntimeSessionManager
  ├─ Electricity / Collection / Monitoring
  ├─ Statistics / Alert / Notification
  ├─ Chat Identity / Internal API
  └─ Repository / SQLAlchemy
              │
              ▼
           SQLite + Alembic

FastAPI Runtime Client ──→ 北邮 CAS / 电费业务站点
FastAPI Notification ────→ AstrBot Bridge Plugin ──→ QQ
QQ 命令 ─────────────────→ AstrBot Bridge Plugin ──→ Internal API
```

完整图见 [system-architecture.md](diagrams/system-architecture.md)。

## 核心模块与职责

| 模块 | 责任 | 不负责 |
| --- | --- | --- |
| `AuthBootstrapService` | 临时 CAS 登录、验证并提取业务 Cookie | 长期持有 CAS Client |
| `RuntimeSessionManager` | 按用户缓存、恢复、锁定和关闭 Runtime Client | 用户业务规则、Scheduler 编排 |
| `ElectricityService` | 上游查询、快照保存与 source_time 去重 | 预警规则、通知发送 |
| `CollectionService` | 当前用户单次采集与状态更新 | 遍历全体用户 |
| `MultiUserCollectionScheduler` | 每日枚举已启用宿舍并限制并发 | 上游 Session 或 Alert 规则 |
| `MonitoringService` | 编排查询、保存、Alert 评估和通知触发 | 全局用户锁 |
| `StatisticsService` | 从只读数据源计算统计与预测 | 写入派生数据 |
| `AlertService` | 用户阈值与 AlertEvent 生命周期 | AstrBot 调用 |
| `NotificationService` | 按事件阶段创建/更新投递记录 | 修改 AlertEvent 状态 |
| AstrBot 插件 | QQ ID/UMO 路由、QQ 命令、Bridge 消息发送 | 保存北邮凭据或 FastAPI Cookie |

## 关键设计

### 认证分离

CAS 登录使用短生命周期 Bootstrap Client。成功后仅提取经过 allowlist 限制的 `eai-sess` 与 `UUkey`，关闭 Bootstrap Client，再构造 App-only Runtime Client。这样 Runtime Client 不携带 `auth.bupt.edu.cn` Cookie、CAS ticket 或登录表单状态。

### 用户隔离

本系统 `User`、浏览器 App Session、加密 upstream session、宿舍配置、Alert、通知绑定和聊天身份均显式以 `user_id` 作用域访问。Runtime Client Pool 使用 `dict[user_id, BUPTClient]`，同一用户的上游请求由独立 `asyncio.Lock` 串行，不同用户可并行。

### 事件驱动与通知解耦

采集成功后的 `MonitoringService` 调用 Alert 评估；Alert 只返回状态变化，NotificationService 才处理 `activated`、`escalated`、`resolved` 投递。通知错误不会回滚电费快照或 Alert episode。

## 安全边界

- 浏览器 API 以 App Session Cookie 识别当前用户。
- AstrBot Internal API 以独立 Bearer Token 认证，不能使用浏览器 Cookie 替代。
- FastAPI 仅知道 QQ ID；QQ 私聊所需 UMO 只保留在 AstrBot 插件数据目录。
- 演示数据仅作为后端只读 Data Provider，不进入采集、Alert 或 Notification 链路。
