# 预警与通知生命周期

## 目的

说明用户级低余额、低剩余天数预警及其与 AstrBot 通知的解耦关系。

## Alert 生命周期

AlertService 对一条已保存的真实 `ElectricityReading` 读取对应用户的 `alert_settings`，支持：

- `low_balance`：余额低于 warning / critical 阈值；
- `low_remaining_days`：统计预测天数低于 warning / critical 阈值。

同一 `(user_id, area_id, room_id, alert_type)` 仅维护一个 active episode：

```text
normal → warning → critical → warning → resolved
```

同等级持续命中只更新 active Event 的最近值与时间，不生成额外事件。恢复到阈值外时将 active Event 置为 `resolved`；之后再次命中会创建新的 episode。

## 通知阶段

AlertService 仅返回状态变化，不发送消息：

| 变化 | Notification stage |
| --- | --- |
| 新建 active Event | `activated` |
| `warning → critical` | `escalated` |
| `active → resolved` | `resolved` |

NotificationService 过滤当前用户已启用的 AstrBot/QQ binding，并以 `notification_deliveries` 的唯一约束实现按阶段幂等。一个事件的 activated、escalated、resolved 可分别投递一次。

## 隔离与容错

- 用户 A 的阈值、事件和绑定不影响用户 B。
- 禁用预警不会伪造或自动 resolve 现有 active Event，只阻止新的评估创建状态变化。
- 通知失败仅记录 failed delivery；不回滚快照和 AlertEvent。
- Demo 数据不调用 AlertService 或 NotificationService。
