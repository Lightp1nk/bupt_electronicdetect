# 测试与验证报告

## 目的

记录当前仓库自动化测试覆盖范围与验证边界。测试不得对北邮服务器发起真实请求，使用 fake、mock 或 `httpx` mock transport。

## 自动化测试范围

`tests/` 包含以下类别：

- CAS Bootstrap 与 App-only Runtime Client Cookie allowlist；
- 多用户 App Session、Upstream Session 加密和 Runtime Client 隔离；
- ElectricityRepository 保存与 source_time 去重；
- StatisticsService 每日耗电、平均值、预测成熟度；
- CollectionService、Scheduler 并发限制与用户失败隔离；
- Alert 生命周期、用户阈值隔离与事件幂等；
- Notification binding、delivery 阶段幂等与 Provider 失败容错；
- Chat identity、绑定码、Internal API 和 QQ 查询摘要；
- AstrBot 插件命令逻辑与 Bridge Provider mock；
- Demo Provider 的只读隔离、统计计算及旧前端 mock 路径移除。

运行：

```powershell
.\.venv\bin\python.exe -m pytest -q
cd frontend
npm run build
```

## 运行时验证建议

- 迁移前后确认 Alembic revision 与核心表存在；
- 使用真实 QQ 完成网页绑定码、`/绑定` 和 `/电费` 的人工联调；
- 通过受控测试 Alert 验证 NotificationDelivery，而非等待真实低余额；
- 检查 FastAPI、AstrBot、Nginx 日志不包含密码、Cookie、Token、Authorization Header 或 Fernet Key；
- Scheduler 只检查启动与时区配置，避免人工批量触发上游采集。

## 非测试结论

自动化测试不能替代北邮上游可用性、QQ 平台可用性和生产网络配置验证。相关真实联调应在受控环境记录时间、结果和失败分类，且不记录秘密值。
