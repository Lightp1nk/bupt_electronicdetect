# 软件需求说明书

## 1 引言

### 1.1 项目背景

校园宿舍用电数据通过学校现有服务提供查询。本项目在合法使用本人有权访问的校园服务、遵循正常统一认证流程的前提下，建设一个面向单用户、本地运行的课程项目。系统当前聚焦于宿舍当前用电信息的安全查询；后续迭代计划在取得用户授权的基础上增加历史记录、分析、展示和提醒能力。

### 1.2 项目目标

| 目标 | 状态 |
|---|---|
| 北邮统一认证并建立业务 Session | 已实现并验证 |
| 动态获取校区、楼栋、楼层与宿舍 | 已实现并验证（开发阶段人工运行） |
| 查询并标准化当前宿舍用电信息 | 已实现并验证（开发阶段人工运行） |
| FastAPI 进程内复用一次登录后的 Session | 已实现并验证 |
| 保存历史用电快照 | 已实现但尚未真实验证 |
| 用电统计、趋势展示与剩余时间估算 | 规划中，尚未实现 |
| 可视化 Dashboard 与历史趋势 | 已实现但尚未真实浏览器验收 |
| 低电量提醒 | 规划中，尚未实现 |

### 1.3 项目范围

当前范围是北邮校园电费数据的查询与本地单用户会话管理。系统不实现在线充值、支付、自动缴费、验证码绕过、批量扫描或多用户账号系统。

## 2 用户需求

主要用户为希望查询本人宿舍用电情况的学生。当前典型流程为：用户登录北邮统一认证 → 选择校区 → 选择楼栋、楼层和宿舍 → 查询当前用电信息。FastAPI 模式下，一次登录后可在同一服务器进程内连续请求已提供的受保护接口，无需再次提交密码。

后续用户需求包括查看历史、趋势、预测和预警，均属规划内容。

## 3 功能需求

| ID | 功能 | 输入 | 处理与输出 | 异常情况 | 状态 |
|---|---|---|---|---|---|
| FR-001 | 用户认证 | 用户名、密码 | 完成 CAS 登录，建立 app Session | 网络、超时、凭据或认证页异常 | 已实现并验证 |
| FR-002 | 认证状态维护 | 当前进程状态 | 真实调用业务接口判断有效性 | Session 失效后清理 client | 已实现并验证 |

| FR-004 | 楼栋列表获取 | `area_id` | 调用 `/part`，输出 `Building` 列表 | 上游业务、解析或 Session 错误 | 已实现并验证 |

## 4 非功能需求

- **安全性**：不永久保存统一认证密码；不记录密码、Cookie 值、CAS ticket 或动态 `execution`；Session 仅驻留服务端进程内；不绕过学校认证机制。
- **可靠性**：使用真实业务请求检查 Session，而非仅检查 Cookie；Session 失效后清理 client 并要求手动重新登录。
- **可维护性**：Provider 层将学校字段转换为 Pydantic 内部模型；统一使用 `ApiResponse[T]` 与 `ErrorCode`。
- **可测试性**：业务解析、Session 管理和 FastAPI 路由有离线 Mock 测试；普通测试不访问学校服务。
- **性能与使用边界**：当前是单用户本地课程项目，不声明并发性能指标；交互探针只查询用户选定范围，不进行高频或批量访问。
- **易用性**：探针以交互方式列出上游返回的显示名称，内部 ID 不要求用户手工填写。

## 5 运行环境

当前依赖在 `requirements.txt` 中声明：Python、httpx、BeautifulSoup4、Pydantic v2、FastAPI、Uvicorn、pytest。当前开发机的 MSYS Python 环境需要使用 MSYS 对应的 Pydantic v2 与 pytest 包；此为开发环境限制，不是业务功能。

SQLite、SQLAlchemy、统计或图表库均为计划采用，当前未加入依赖。

## 6 限制与约束

- 上游校园服务、接口格式和 Session 生命周期由学校系统决定，可能变化。
- 当前只支持一个 FastAPI 进程中的一个当前登录账号。
- 服务重启会丢失内存 Session，用户需重新认证。
- 系统不提供支付或自动缴费功能。
- 只应查询用户有权访问的数据，不扫描无关楼栋或宿舍。
